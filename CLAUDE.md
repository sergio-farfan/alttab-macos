# CLAUDE.md

Guidance for Claude Code sessions in this repo (AltTab — Windows-style window switcher for macOS, pure Swift/AppKit, zero dependencies).

## Build & Test

- `swift test` — unit tests for the `AltTabCore` module via the SPM harness in `Package.swift`; run plainly, no output-truncating pipes. CI runs them on every push/PR (`tests.yml`) and as a gate at the top of `release.yml`, so a red test blocks a release. Most suites are pure logic (`MRUOrder`, `SwitcherStateMachine`, `SwitcherSelection`, `GatherMerge`, `Debouncer`), but `WCAGContrastTests` resolves **live OS semantic colors** in both appearances — an OS/SDK update can retune a system color and fail an AA-boundary assertion with no code regression, so check that before hunting phantom logic bugs.
- `xcodebuild -project AltTab/AltTab.xcodeproj -scheme AltTab -configuration Release build` — app build
- **No Xcode, only Command Line Tools?** `swift test` fails with "no such module 'XCTest'" (CLT ships no XCTest) and `xcodebuild` is a dead shim — but `swiftc -typecheck -target arm64-apple-macos13.0 AltTab/AltTab/*.swift` type-checks every app source against the CLT SDK, and a scratch `main.swift` compiled together with a core file (`swiftc AltTab/AltTab/SwitcherStateMachine.swift main.swift`) exercises pure logic without XCTest. Neither runs the real event tap; that needs an installed build.
- `./build.sh install` — build + install to `~/Applications` (dev installs live there, not `/Applications`)
- `scripts/package-dmg.sh <version>` — universal (arm64+x86_64) Release, ad-hoc seal, DMG + sha256 into `dist/` (gitignored; CI artifact is canonical)
- `swift scripts/generate-appicon.swift` — regenerates all AppIcon PNGs parametrically (pure AppKit, no design tools)

## Architecture Invariants

- `WindowModel` state (MRU order, cache, `pendingActivation`, `focusEpoch`, observers, debouncer) is **main-thread-confined**. Off-main work is stateless or hops back: the static gather on `gatherQueue` (per-app AX pass fans out via `concurrentPerform`), the focused-window probe on `focusProbeQueue` (promotes via a main hop guarded by `focusEpoch`), icon resolution on `AppIconCache.resolveQueue`. Never mutate WindowModel state off-main — and never run AX IPC **on** the main thread: it services the event tap, and a stall gets the tap disabled by timeout (the cold-cache path deliberately serves a CG-only list for exactly this reason).
- `AXUIElementSetMessagingTimeout` is **per-element** — set it on each AX *window* element too, not just the app element, or per-window fetches keep the ~6s default.
- The `sources:` allow-list in `Package.swift` is the authoritative set of files compiled into BOTH the app target and the SPM `AltTabCore` module (`MRUOrder`, `SwitcherStateMachine`, `SwitcherSelection`, `WCAGContrast`, `GatherMerge`, `Debouncer` as of 1.3.2 — trust the manifest over this list): keep every file on it free of AppKit imports.
- New Swift files must be registered by hand in `project.pbxproj` (classic explicit refs — mirror the existing `A1…`/`A2…` PBXBuildFile/PBXFileReference/group/Sources pattern). Files that belong in AltTabCore must ALSO be added to the `sources:` allow-list in `Package.swift` — it is an allow-list, so a new core file will not compile into the test module without it ("cannot find type in scope" from `swift test` means this). The `exclude:` list is inert legacy given the explicit `sources:`; app-only files need no Package.swift change.
- No ScreenCaptureKit API **and no `CGRequestScreenCaptureAccess()`** may execute unless the `ShowWindowPreviews` default is on — never prompting for Screen Recording by default is a core product promise (README, CHANGELOG 1.2.0). The prompt is raised by the CoreGraphics call, not only by SCK symbols; `CGPreflightScreenCaptureAccess()` is the safe, never-prompting check.
- `NSGlassEffectView` (Liquid Glass background) exists only in the macOS 26 SDK — `#available` gates runtime, not compile time, so builds require Xcode 26+; `release.yml` runs on `macos-26` for this reason. Glass content must be embedded via its `contentView` property (header contract). macOS 26.5 auto-pins the assigned contentView edge-to-edge, but the explicit constraints in `SwitcherPanel.installBackground` are **deliberate agreeing duplicates** — 26.0–26.4 is not claimed to auto-pin, so keep them; re-examine on major OS updates. `NSGlassEffectView` has **no intensity API** (only `style` regular/clear, `tintColor`, `cornerRadius`, `contentView`): the Glass Strength levels are emulated — Light/Medium make the `contentView` host a translucent window-background `NSBox` plate over the glass, Max uses `.clear` — with the mapping in the pure `GlassStrength` type (unit-tested).
- Async completions in `AppDelegate` **belonging to a switcher session** (refresh, previews) are guarded by `switchSession` epoch + `switcherActive`; preserve that pattern for new session-scoped async work. Launch-path async (the permission recheck, the `.accessibilityGranted` observer) is correctly unguarded — those guards can never pass outside a session, so wrapping launch work in them dead-codes it silently.

## Signing & TCC (hard-won)

- Shipped bundles MUST be codesign-sealed. Building with `CODE_SIGNING_ALLOWED=NO` alone yields an unsealed bundle (linker-signed arm64 slice only) → macOS fabricates unpredictable code identities → the TCC Accessibility toggle shows ON while the binary is denied and no event tap is created. `package-dmg.sh` applies `codesign --force --deep -s - --identifier com.alttab.app` when `SIGN_IDENTITY` is unset.
- Ad-hoc identity changes every build → each release legitimately re-prompts Accessibility once. Stuck grant: `tccutil reset Accessibility com.alttab.app`, relaunch, re-grant.
- Debugging TCC: read `csreq` from `/Library/Application Support/com.apple.TCC/TCC.db` (sqlite3), decompile with `csreq -r <file> -t`, compare with `codesign -dvvv` cdhash; verify the tap exists with a `CGGetEventTapList` probe. Reading TCC.db requires the **invoking process to have Full Disk Access** — without it sqlite3 fails with "authorization denied" (the file mode is world-readable but TCC-protected, and `sudo` does not help; grant FDA to the terminal).
- Launching the app from a shell is an INVALID test of its own TCC state (the terminal becomes the responsible process and its grants leak in) — always test via `open` / LaunchServices.
- The unified log can be unreliable for this app: on at least one dev machine `log show --predicate 'process == "AltTab"'` returned nothing even for fresh NSLog output. Verify `log show` works on your machine before relying on it for diagnostics.

## Release Process

1. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.pbxproj`. These drive **dev/local builds only** (Info.plist substitutes them): for shipped artifacts, `package-dmg.sh` PlistBuddy-overwrites `CFBundleShortVersionString` from the **git tag** and `CFBundleVersion` from CI, so the tag is the real version source and nothing checks tag-vs-pbxproj consistency — keep them in agreement by hand. `CURRENT_PROJECT_VERSION` is a monotonic dev-build counter, not the marketing version; don't "fix" it to match.
2. Add a `## [X.Y.Z]` CHANGELOG section plus the link reference at the bottom (Keep a Changelog format). The heading must match exactly: `changelog-section.sh` failure is swallowed in `release.yml` (`|| echo`), so a mis-titled section silently ships a one-line release body, and re-running the tag cannot repair it (the re-run path is `gh release upload --clobber`, which never touches notes — recovery is `gh release edit`).
3. Commit to `main` (direct push bypasses the PR rule via admin — matches release precedent), annotated tag `vX.Y.Z`, push branch + tag.
4. `release.yml` triggers on `v*` tags → builds and publishes the DMG (~1 min). CI stamps `CFBundleVersion = major*10000+minor*100+patch.runN`. Developer ID signing **and notarization both key on the single secret `MACOS_CERTIFICATE_P12_BASE64`**: setting it without the rest (cert password, keychain password, notary `APPLE_API_KEY_ID`/`APPLE_API_ISSUER_ID`/`APPLE_API_KEY_P8_BASE64`) makes the notarize step run with empty credentials and abort the job after the tag is pushed — no assets published. Set all the secrets together or none. (The identity comes from a keychain grep; no team-id secret is used.)
5. **Homebrew tap** (`github.com/sergio-farfan/homebrew-tap`, cask `alttab`, install: `brew install --cask sergio-farfan/tap/alttab`). The last release step sends a `repository_dispatch` (`alttab-release`: version + sha256) that runs the tap's `bump.yml` (`brew bump-cask-pr --write-only --commit`, validate, push) — **dormant until the `TAP_DISPATCH_TOKEN` secret exists** (fine-grained PAT scoped to the tap repo, Contents: read/write); until then, or if it fails, edit `version`/`sha256` in the tap's `Casks/alttab.rb` or run its `bump.yml` by hand. Test the secret without releasing: `gh workflow run release.yml -f version=<current released version> -f notify_tap=true` — HTTP 401 from the notify step means the stored token string is not a live token (re-set it), 403 means wrong permissions/scope. Gotcha: `brew tap` of an *untrusted casks-only* tap fails with a misleading "invalid syntax in tap" — run `brew trust sergio-farfan/tap` first, or install fully qualified (which auto-trusts just the cask). Cask validation (`brew style`/`audit`) runs in the tap's CI, not locally.
